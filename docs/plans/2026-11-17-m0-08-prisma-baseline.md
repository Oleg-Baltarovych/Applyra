## Design
**Schema** (`apps/api/prisma/schema.prisma`): models exactly as 05 §4.2 minus everything under `// R1+`/`// R1` and minus back-relations to models that do not exist yet (`ownedJobs`, `applications`, `applicationEvents`, `reminders`, `importSessions`, `idempotencyRecords` → M1-01). `UserSettings`: `timezone`, three stale ints, `hotkeysEnabled`, `updatedAt` only. Enums: only `Role` (USER, ADMIN — one value per line); other R0 enums arrive with their models in M1-01. `Account.password` — see open question 1 (default: excluded, spec marks R1).

**prisma.config.ts** (CLI only; runtime never reads it): `schema`, `migrations.path`, `datasource.url = process.env.MAINTENANCE_DATABASE_URL ?? ''`, `shadowDatabaseUrl = process.env.SHADOW_DATABASE_URL ?? ''` — `process.env` not `env()` because `env()` throws on a missing var even for `generate` (verified, Prisma config reference). Prisma 7 loads no `.env` (verified): load the root `.env` with `process.loadEnvFile` **only if `MAINTENANCE_DATABASE_URL` is unset and the file exists** → explicit env (Testcontainers, CI, migrate container) always wins and a dev `.env` can never redirect test migrations to the local DB. No `dotenv` dependency (05 §2.1 snippet updated). `prisma.config.ts` still works on 7.10 (new `prisma7.config.*` is preferred only if present — verified 7.10.0 notes). Verify at implementation: `loadEnvFile` precedence/missing-file behaviour (Node 24 docs silent in what was read).

**`src/platform/prisma/`** (rule 4: only `*.repository.ts` + `platform/**` import it; services import only `transaction.ts`)
- `prisma.client.ts` — `createPrismaClient({ url, scopeMode, logger })` → `new PrismaClient({ adapter: new PrismaPg({ connectionString: url }) }).$extends(userScope(...))`; `type AppPrisma = ReturnType<typeof createPrismaClient>`. Keeps the base client for `$disconnect` (extended clients may lack client-level methods — Prisma docs).
- `prisma.module.ts` — `@Global()` `PrismaModule`, provider token `PRISMA` (factory from `ConfigService`: `DATABASE_URL`, mode from `NODE_ENV`), `TransactionRunner`; `OnApplicationShutdown` → `$disconnect` (`main.ts` already calls `enableShutdownHooks`). **No eager connect** (adapter-pg connects lazily) → in-process tests boot without a DB; readiness probe = M0-09.
- `user-scope.domain.ts` (pure, coverage gate applies) — `USER_SCOPED_MODELS: Readonly<Record<string, string>>` = `{ UserSettings: 'userId' }` (M1-01 adds `Application`, `ApplicationEvent`, `Reminder`, `ImportSession`, `IdempotencyRecord`; `Job`/`ownerId` decided there because `findAccessibleJob` uses `OR`). Auth tables (`User`, `Session`, `Account`, `Verification`) are **deliberately absent**: Better Auth queries by token/id/email, and `User` is the identity itself → no false positives by construction. `isOwnerScoped(where, field)`: true iff `where[field] !== undefined` (any operator object counts), or a compound-unique key whose `split('_')` contains `field` with an object value, or a top-level `AND` (object or array) element is scoped. `OR`/`NOT`/`field: undefined` (Prisma drops undefined filters) do **not** count. Checked ops: `findUnique(OrThrow)`, `findFirst(OrThrow)`, `findMany`, `update(Many|ManyAndReturn)`, `upsert`, `delete(Many)`, `count`, `aggregate`, `groupBy`. `create*` skipped (NOT NULL FK enforces owner). Raw queries (`model` undefined) skipped — raw helpers are reviewed + own tests.
- `user-scope.extension.ts` — `$allModels.$allOperations` hook; mode `throw` → `UnscopedQueryError(model, operation)` (no arg values in message: PII), `warn` → Nest `Logger.warn` (pino in M0-09), `off` → no extension. Limitation (documented): nested reads/writes and relation `include` are not intercepted (Prisma docs) — IDOR tests remain the primary defence.
- `transaction.ts` — `@Injectable() TransactionRunner.run<T>(fn: (tx: Tx) => Promise<T>): Promise<T>`; `Tx` = opaque branded type (no Prisma API). `run` creates a frozen token, stores token→tx client in a `WeakMap`, deletes it in `finally`. `prisma-tx.ts` (repositories only): `clientFor(tx?: Tx): AppPrisma | TxClient` — lookup, no casts; a token used after commit throws. Verify at implementation that the interactive-tx client carries the query extension (docs silent) — AC 6 test proves it.
- `index.ts` — exports `PrismaModule`, `PRISMA`, `AppPrisma`, `TransactionRunner`, `Tx`.

**Better Auth** (`auth.options.ts`): `inject: [ConfigService, PRISMA]`, `database: prismaAdapter(prisma, { provider: 'postgresql' })` from `better-auth/adapters/prisma` (verified docs; Prisma 7 + adapter supported, Prisma 8 not). Pass the extended client; fallback to the base client only if adapter types reject it (comment why). Add `deletedAt: { type: 'date', required: false, input: false }` to `additionalFields` (05 §2.3; missing since M0-02). `generateId` v7 unchanged.

**Tests touched**: `auth-bootstrap.test.ts` stays in-process on the memory adapter (HTTP guard/body/`input:false` behaviour is store-independent; it needs `Account.password`). `config-bootstrap.test.ts`: the allowlisted `createUser` case now writes to Postgres → moves to `test/integration/auth-persistence.test.ts`; rejection + config assertions stay in-process (hook throws before any DB call).

**Migration script** `apps/api/scripts/db-migrate.mjs` (single source of the REVOKE): requires `MAINTENANCE_DATABASE_URL` (loads root `.env` only if unset, same rule) → spawns the local Prisma CLI `migrate deploy` → as maintenance `REVOKE INSERT, UPDATE, DELETE, TRUNCATE ON "_prisma_migrations" FROM applyra_app` → asserts via `has_table_privilege` (exit 1 otherwise). Never prints URLs. Scripts: `@applyra/api db:migrate`, root `pnpm db:migrate`; `db:migration <name>` = ensure `applyra_shadow` exists (superuser from `SHADOW_DATABASE_URL`; Prisma does not create a manually configured shadow DB, it resets it — verified) → `prisma migrate dev --create-only --name <name>` → edit untracked SQL (guard hook allows) → `db:migrate` (never `migrate dev` apply: it would skip the REVOKE).
**Testcontainers** `applyMigrations(url)`: `execFile(process.execPath, ['scripts/db-migrate.mjs'])`, cwd `apps/api`, env = `{ PATH, MAINTENANCE_DATABASE_URL }` (+ `SystemRoot`, `TEMP` on win32) taken from `runner-env.ts` (only process.env reader). Test client helper `test/integration/support/prisma.ts` → `createPrismaClient({ url: testInfra().databaseUrl, scopeMode: 'throw' })`.

**CI** job `migrations` (name `migrations`, `if != schedule`, ~5 min): checkout `fetch-depth: 0` → setup → (a) guard: any M/D/R under `apps/api/prisma/migrations/` vs base (`pull_request.base.sha` / `event.before`) → fail; (b) squawk (release binary pinned version + `sha256sum -c`, latest seen v2.73.0 of 2026-11-15 — pin a ≥ 24 h old one; verify asset name at implementation) on added `migration.sql`, `.squawk.toml` at repo root (`pg_version`, `assume_in_transaction = true`; every `excluded_rules` entry with a reason comment); (c) `docker run postgres:18.7` (same tag as `test/support/images.ts`) on `127.0.0.1`, passwords `openssl rand` + `::add-mask::`, roles script via `docker exec -e VAR` (values from env, not argv); (d) clean apply `pnpm db:migrate`; (e) `CREATE DATABASE applyra_shadow`, `prisma migrate diff --from-migrations prisma/migrations --to-schema prisma/schema.prisma --exit-code` (flags verified Prisma 7; shadow from config). Runs on every PR (superset of 11 §9 "if prisma/ changed": no path filter, no skipped-required-check ambiguity). Required checks += `migrations`.

**Generated client**: gitignored; turbo task `db:generate` (inputs `prisma/schema.prisma`, outputs `src/platform/prisma/generated/**`) as dependency of `typecheck`, `build`, `test`, `test:integration`, `lint` if import resolution needs it; excluded from Prettier/ESLint. Verify at implementation: pnpm 11 `allowBuilds` for `prisma` / `@prisma/engines` (schema engine download) — allow with reason, or `false` if not needed.

## Security notes
- Runtime never holds DDL or maintenance creds; `MAINTENANCE_DATABASE_URL`/`SHADOW_DATABASE_URL` are CLI-only (not in `env.schema.ts`; `env-example.test.ts` allowlist updated if it requires it).
- `_prisma_migrations` REVOKE + ACL allowlist make privilege drift a red test; `UnscopedQueryError` carries model/op only.
- Script/CI never echo connection strings; CI passwords masked and per run.

8. `docs: M0-08 context` — CONTEXT §1–3, §6 (Prisma CLI env rule, `db:migrate`/`db:migration`, generated dir, migrations job + required check, user-scope list lives in `user-scope.domain.ts`, **Windows-local flake: `test:integration` once exited 0xC0000409 before any test ran; rerun passed, Ryuk cleaned up — rerun once, open an issue if it repeats**); 05 §2.1 snippet (MAINTENANCE url, no dotenv, `process.env`), 11 §9 (migrations on every PR), ADR 016 amendment (ESM client per M0-02 instead of CJS; CLI env rule).
