# M0-11 · `GET /me` + `PATCH /me/settings`

FR-PROF-01 (+ FR-AUTH for `/me`) · GitHub #14 · spec `06-api.md` §1, §3, §7.1 · `05-data-model.md` UserSettings + CHECK `user_settings_ranges_chk` · `11-testing.md` §4 p.5 · `04-architecture.md` §3 (`users` → `auth`) · branch `feat/M0-11-me-settings` · deps: none new.

## Goal
First real private routes: the SPA (M0-12) learns who is signed in and edits preferences. They go through the M0-07b IDOR gate as `@IdorExempt` (11 §4 p.5 names `GET /me` as the example).

## Acceptance criteria (mvp-tasks M0-11 → test)
1. `GET /api/v1/me` with a session → 200 `Me` = `{ user: { id, email, name, image, createdAt }, settings: UserSettings }` (`expectContract`); no `role`, `deletedAt`, `demoExpiresAt`, tokens. Without a session → 401 `UNAUTHENTICATED`.
2. `PATCH /api/v1/me/settings` accepts any non-empty subset of `timezone`, `staleFollowUpDays` (1–90), `staleDaysAfterInterview` (1–90), `staleGhostDays` (1–180), `hotkeysEnabled`; returns 200 with the full updated `UserSettings`; only passed fields change.
3. `.strict()`: unknown key (incl. `userId`, `updatedAt`) → 400 `VALIDATION_ERROR`, `details[].path` = key; `{}` → 400; `null` for any field → 400 (none is nullable); out-of-range / non-integer → 400; DB row unchanged after each.
4. Invalid IANA zone (`Mars/Base`, `+02:00`, `GMT+7`, `""`, > 64 chars) → 400 `VALIDATION_ERROR` path `timezone`; valid (`Europe/Kyiv`, `America/Argentina/Buenos_Aires`, `UTC`, `Etc/GMT-3`) → stored in engine-canonical form (`europe/kyiv` → `Europe/Kyiv`).
5. `UserSettings` exists after first sign-in: the first `GET /me` creates the row with DB defaults (UTC, 7/10/21, true) — race-free (two concurrent first calls → one row, both 200). See Q1 for the browser-timezone marker.
6. Isolation: A's PATCH never changes B's row; B's `GET /me` never contains A's id/email.
7. Both routes `@IdorExempt(reason)`, listed in `EXPECTED_EXEMPT_ROUTES`; `PATCH` also in `EXEMPT_ALLOWLIST` with a comment; `pnpm test` IDOR gate green (coverage + 401 probe).
8. Mutation without `Origin: WEB_ORIGIN` → 403 `CSRF_ORIGIN` (existing HttpPolicyGuard; one regression test).

## Decisions
**Fixture vs exemption → exemption.** Neither route takes an id in path/query/body; `userId` comes only from the Better Auth session (`@Session()`); `.strict()` rejects any smuggled `userId`. The fixture model (B requests A's resource → 404) has nothing to address: B's own `/me` is a legitimate 200. Cross-user isolation is still tested explicitly (AC 6) in the module's integration test, not via the runner.

**Owner = `users` module** (04 §3 owns User + UserSettings; dependency `users → auth`). Creating the row in a Better Auth `user.create.after` hook would make `auth` import `users` (inverted edge) — so the row is ensured lazily by `UsersService` on `GET /me` (and before `PATCH`). Insert = `createMany({ data: [{ userId }], skipDuplicates: true })` (`ON CONFLICT DO NOTHING`, no P2002 race; create* is not checked by the user-scope extension, FK pins the owner) → then `findUnique({ where: { userId } })`. Defaults stay in the DB only (single source).

**Timezone validation lives in contracts** (shared with the M0-12 form): `IanaTimeZone = z.string().max(64).regex(/^[A-Za-z][A-Za-z0-9_+-]*(\/[A-Za-z0-9_+-]+)*$/)` (rejects offset strings, which newer ECMA-402 engines accept as `timeZone`) `.refine(accepted by new Intl.DateTimeFormat('en-US', { timeZone }))` `.transform(resolvedOptions().timeZone)`. `Intl` is ECMAScript, not a Node/browser API (contracts rule holds). Do not use `Intl.supportedValuesOf('timeZone')` — V8 omits `UTC`.

**`/api/v1` prefix** (06 §1; not set yet — routes are at root). Proposed here as step 1 (Q2): `app.setGlobalPrefix('api/v1', { exclude: ['health/live', 'health/ready'] })` in `configureHttp` (`12-infra-ops.md` api host row lists `/health/*` outside `/api/v1`); `buildRouteTable` learns exact-path excludes (today it throws on any foreign exclude). Verify at implementation how thallesp merges its `/api/auth` excludes with ours (order: our `setGlobalPrefix` runs before `init`).

## Design
**Contracts** `packages/contracts/src/me.ts` (export from `index.ts`): `IanaTimeZone`, `STALE_DAYS_LIMITS` (`{ followUp: [1,90], afterInterview: [1,90], ghost: [1,180] }` = CHECK), `UserSettings` (`timezone, staleFollowUpDays, staleDaysAfterInterview, staleGhostDays, hotkeysEnabled` [+ `timezoneConfirmed` if Q1-A]), `UpdateUserSettings` = `z.strictObject({...all optional, non-nullable})` + refine "at least one field" (path `""`), `MeUser`, `Me`. Schema + inferred type per name.

**API** `apps/api/src/modules/users/`: `index.ts` (UsersModule, `UsersService` — 04 §3 `getSettings` for R1 consumers), `users.module.ts`, `me.controller.ts` (`@Controller('me')`; `@Get()` + `@Patch('settings')`, `@IdorExempt(...)`, `@Session() session`, `createZodDto(UpdateUserSettings)` body, `@ZodResponse`/serializer DTO from `Me`/`UserSettings` — verify nestjs-zod 5.6 decorator name), `users.service.ts` (`getMe(userId)`, `updateSettings(userId, patch)` = ensure + update in one `TransactionRunner.run`), `users.repository.ts` (`findOwnedUser(userId)` selects only `MeUser` fields; `ensureOwnedSettings`, `findOwnedSettings`, `updateOwnedSettings` — all `where: { userId }`), `settings.domain.ts` only if Q1-A (`toSettingsUpdate(patch)`: sets `timezoneConfirmed: true` iff `timezone` present). Register `UsersModule` in `AppModule` after `AuthModule`.
User row missing (impossible while the session FK cascades) → `AppException('NOT_FOUND')`, not 500.

**DB**: none unless Q1-A → new migration `user_settings_timezone_confirmed` via `/prisma-migration`: `SET lock_timeout/statement_timeout`; `ALTER TABLE "UserSettings" ADD COLUMN "timezoneConfirmed" BOOLEAN NOT NULL DEFAULT false;` (constant default → metadata-only on PG 18, no rewrite); `migrate diff --exit-code` clean; squawk green.

**IDOR registry**: `EXPECTED_EXEMPT_ROUTES` += `GET /api/v1/me` ("self-scoped: user from session, no id input"), `PATCH /api/v1/me/settings` ("self-scoped: writes only the session user's settings row; strict body has no id"); `EXEMPT_ALLOWLIST` += `PATCH /api/v1/me/settings` with a comment. Update the `fixtures.ts` header comment.

## Security notes
Authz = session only (API1); mass assignment closed by `.strict()` + response serializer (API3); body limit 1 MB and CSRF Origin already global (M0-09). Response never carries role/flags (least data). Logs: no body logging of settings needed; email in `/me` response is not logged (pino logs req/res meta only).

## Implementation notes (deviations)
- AC 4 canonicalisation: V8/ICU resolves links to legacy names (`Europe/Kyiv` → `Europe/Kiev`, `America/Argentina/Buenos_Aires` → `America/Buenos_Aires`, `Asia/Kolkata` → `Asia/Calcutta`; Firefox does not). Review fix: `IanaTimeZone` stores the id as sent (no case or alias canonicalisation; `europe/kyiv` stays as sent), only `utc` in any case → `UTC`; documented in 06 §7.1.
- Unknown keys: Zod reports them in one `unrecognized_keys` issue on the object; `error-mapping.domain.ts` now emits one detail per key (`path` = key, message `Unknown field`).
- Migration SQL generated with `prisma migrate diff --script` (the local dev DB has an outdated `init` checksum, so `pnpm db:migration` wanted a reset); drift check clean, applied in Testcontainers via `db-migrate.mjs`.
