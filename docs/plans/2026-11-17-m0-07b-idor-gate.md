# M0-07b · IDOR gate skeleton

FR-AUTH-03 · GitHub #10 · spec `11-testing.md` §4 (T-02), `09-security-privacy.md` §2 + §15 (API1/API5) · branch `feat/M0-07b-idor-gate` · deps: none new.

## Goal
Make it impossible to add a private route without an IDOR fixture or an explicit, reasoned exemption, and without the auth guard. Today every route (`/health/*`) is `@Public`, so the gate passes empty; M0-11 (`GET /me`, `PATCH /me/settings` → `@IdorExempt`) and M1-04 (`/jobs/:id` fixtures) are the first consumers.

## Acceptance criteria
1. Route table built from the real `AppModule` via `DiscoveryService` + `MetadataScanner` + `Reflector`: `{ method, path, isPublic, isOptional, roles, idorExempt, controller, handler }`.
2. Coverage gate: `nonPublic − fixtures − exempt ≠ ∅` → fail listing `"<METHOD> <path>"`; a fixture for a non-existent route → fail; exempt list + reasons printed.
3. Protection gate: every non-`@Public`, non-`@OptionalAuth` route answers **401 `UNAUTHENTICATED`** to a cookie-less request (with `Origin: WEB_ORIGIN`); global guards include thallesp `AuthGuard` before `SessionLifetimeGuard`.
4. Self-test: a test-only controller with an unfixtured private route makes the coverage gate fail (names it); the same route in an app without `AuthModule` makes the protection gate fail.
5. `@IdorExempt('')` throws at decoration time; class-level use is not supported (handler only).
6. Typed fixture registry + generic runner exist (integration); empty registry runs green.

## Design
**Decorator** `apps/api/src/platform/http/idor-exempt.decorator.ts`, exported from `platform/http/index.ts` (precedent: `@AcceptsMultipart`; modules already import `platform/http` via index, so boundaries allow it; no dependency on `auth`). `IdorExempt(reason: string): MethodDecorator` → `SetMetadata(IDOR_EXEMPT_KEY, reason)`; trims, throws on empty. Handler-only so a new route in an exempt controller is never silently exempt. Runtime no-op (metadata only).

**Public/optional detection**: thallesp 2.8.0 `dist/index.mjs` sets string keys `"PUBLIC"`, `"OPTIONAL"`, `"ROLES"` (verified; no exported constants) read via `getAllAndOverride([handler, class])`. Add `AUTH_METADATA = { public: 'PUBLIC', optional: 'OPTIONAL', roles: 'ROLES' } as const` to `modules/auth` (exported from `index.ts`), use it in `session-lifetime.guard.ts` too (removes the duplicated literals). Plus a unit test that `@Public()` / `@OptionalAuth()` actually write those keys — catches a package rename on upgrade.

**Route table** `apps/api/test/support/route-table.ts` — `buildRouteTable(app: INestApplication): Route[]`:
- `app.get(DiscoveryService).getControllers()` → for each wrapper with `instance`, `app.get(MetadataScanner).getAllMethodNames(proto)`; keep methods with `METHOD_METADATA`; path = global prefix (`app.get(ApplicationConfig).getGlobalPrefix()`, empty today) + controller `PATH_METADATA` + handler `PATH_METADATA`, normalised (`/a/:id`, no trailing slash; array paths → one row each). `RequestMethod` enum → `'GET' | …`.
- Flags via `Reflector.getAllAndOverride` with `AUTH_METADATA` / `IDOR_EXEMPT_KEY`.
- Better Auth `/api/auth/*` is middleware, not a controller → not in the table (by design; covered by auth-flow tests). Versioning (`/api/v1`) not enabled yet — if added via `enableVersioning`, extend here (verify at implementation).

**Gate logic** `apps/api/test/support/idor-gate.ts` (pure, unit-tested): `checkCoverage(routes, fixtureKeys) → { uncovered[], unknownFixtures[], exempt[] }`; `formatReport()`.

**Protection probe** (same file): for each private route, Supertest request with path params filled by a fixed UUID v7, no cookie, `Origin: WEB_ORIGIN`, empty JSON body for mutations → expect 401 + `code: UNAUTHENTICATED`; collect failures. Black-box = robust against per-route `@UseGuards` overrides or a missing global guard. Extra structural check: `app.get(ApplicationConfig).getGlobalRequestGuards()` metatypes contain `AuthGuard` then `SessionLifetimeGuard` (verify at implementation that `APP_GUARD` providers land there in Nest 11.2).

**Fixture registry** `apps/api/test/idor/fixtures.ts` (spec path) + `define-idor-fixture.ts`:
```ts
type RouteKey = `${'GET'|'POST'|'PATCH'|'PUT'|'DELETE'} /${string}`;
interface IdorFixture {
  route: RouteKey;
  kind: 'by-id' | 'list' | 'create-ref';         // 11 §4 table
  setup(ctx: { prisma: AppPrisma; owner: SignedIn }): Promise<{
    params?: Record<string, string>; query?: Record<string, string>; body?: unknown;
    ownedIds: string[]; snapshot?: () => Promise<unknown> }>;  // snapshot: DB state of A's resource
}
export const defineIdorFixture = (f: IdorFixture) => f;
export const idorFixtures: readonly IdorFixture[] = [];       // M1-04 adds jobs, M1-0x applications…
```
Runner `apps/api/test/integration/idor.test.ts`: `signInAs(A)`, `signInAs(B)` (real auth path), `setup` as A, request as B: `by-id`/`create-ref` → 404 `NOT_FOUND` via `expectContract` + `snapshot()` before/after equal; `list` → 200, no `ownedIds` in body. `it.each` over the registry; `it.skip`-free when empty (one sentinel test asserts the registry loaded). `@Roles('ADMIN')` → USER 404 case: deferred until the first admin route (R1).

**Where it runs**: coverage + protection gate in-process `apps/api/test/idor-gate.test.ts` (`pnpm test`, CI `unit`; AppModule boots without Postgres — lazy connect; verify at implementation that a cookie-less AuthGuard call never touches the DB). Fixture runner in `test:integration` (needs DB). Both are existing CI jobs — no workflow change.

## Security notes
Gate is the API1/API5 control from 09 §15; exemptions are reviewable (reason mandatory, printed). `@OptionalAuth` routes still need a fixture/exemption; they skip the 401 probe but are listed in the report.

## Steps (one commit each, test-first)
1. `auth`: `AUTH_METADATA` + unit test that `Public()`/`OptionalAuth()`/`Roles()` set those keys; refactor `SessionLifetimeGuard` to use it (existing tests stay green).
2. `platform/http`: failing unit test (`@IdorExempt('x')` metadata on handler; `''`/whitespace throws) → decorator + index export.
3. `test/support/idor-gate.ts`: failing unit tests for `checkCoverage` (uncovered, unknown fixture, exempt, public skipped, optional counted) → implement.
4. `route-table.ts`: test on a `createHttpApp({ controllers: [ProbeController] })` (test-only, `test/support/idor-probe.controller.ts`: public GET, private `GET /probe/:id`, exempt POST, `@OptionalAuth` GET, class+handler path join) asserting exact rows; health rows present.
5. Protection probe + global-guard check; self-test: probe app with `AuthModule` → private route 401 ✓; minimal `Test.createTestingModule({ controllers: [ProbeController] })` app (no guards) → probe reports `GET /probe/:id`.
6. `test/idor-gate.test.ts` on the real AppModule: coverage gate (passes now) + protection gate; self-test case: real AppModule + ProbeController → gate fails listing `GET /probe/:id`.
7. Registry + `defineIdorFixture` + integration runner (sentinel test; type-check a sample fixture in a `*.test-d.ts` or inline `satisfies`).
8. Docs: `CONTEXT.md` (§2 test/idor, §6 gotcha: thallesp metadata keys, exempt handler-only), `11-testing.md` §4 point 1 add `isOptional`/`idorExempt` fields; `.claude/rules/testing.md` one line: "new private route → fixture in `test/idor/fixtures.ts` or `@IdorExempt('reason')`".

## Out of scope
