# Node 24 → Node 26 LTS (+ pnpm without corepack)

- Date: 2026-11-18 · ADR: [024](../adr/024-node-26-lts-and-pnpm-without-corepack.md) (Accepted) · Closes #145 · Spec: `04-architecture.md` §7.1, ADR 002 follow-up
- Supersedes the uncommitted changes on `fix/145-windows-vitest-worker-crash` (`engines ^24.16.0`, CONTEXT §6 #145 line).
- Release fit: platform/tooling, no FR; R0 M0 phase. No behaviour change for users.

## Goal & acceptance criteria
1. Root `package.json` `engines.node` = `^26.13.1`; CI `setup-node` resolves 26.13.x (visible in the job log of every job using `./.github/actions/setup`).
2. `apps/api` `@types/node` = `^26.x` (latest ≥ 24 h old, `minimumReleaseAge: 1440`); lockfile has no `@types/node@24`.
3. `pnpm-workspace.yaml` sets `pmOnFail: download` (comment: why); with a global pnpm 12 the repo runs `pnpm -v` = 11.28.12 (packageManager).
4. Local (Windows, Node 26.13.1) and CI green: `pnpm install --frozen-lockfile`, `lint`, `format:check`, `typecheck`, `test` (domain coverage gate), `test:integration`, `build`, `pnpm audit --audit-level=high`, osv-scanner, gitleaks, actionlint, `migrations` job.
5. `pnpm db:migrate` on the compose DB + drift check (`prisma migrate diff … --exit-code`) pass on Node 26; `pnpm --filter @applyra/api dev` boots and `GET /health/ready` = 200.
6. #145: the repro loop (`apps/api`: `test/auth-bootstrap.test.ts` + `test/http-platform.test.ts`) runs ≥ 30 times on 26.13.1 with **0** crashes (author runs it; result + `process.versions.uv` recorded in the PR body and CONTEXT §6).
7. No new Node deprecation warnings attributable to our code under `--trace-deprecation` (third-party ones listed in the PR body).
8. Docs: README, spec 04 §7.1, CONTEXT (§1/§6), mvp-tasks M0-01/M2-14 lines no longer mention Node 24 or corepack as the bootstrap.

## Design / changes (no app code)
- `package.json`: `engines.node` `^26.13.1`. `packageManager` unchanged (pnpm 12 bump = separate decision).
- `apps/api/package.json`: `@types/node` `^26.<latest>`; regenerate lockfile.
- `pnpm-workspace.yaml`: `pmOnFail: download` + comment "global npm pnpm self-switches to packageManager; ADR 024".
- `.github/actions/setup/action.yml`: no functional change (already engines + packageManager); description/comments mention "no corepack (Node 25+)". No other node-version references exist in `.github/` (checked: every job uses the composite action).
- Dockerfiles: none yet. M0-14 decision recorded: `node:26-trixie-slim` (or a distroless Node 26 image, evaluated in M0-14), digest-pinned, same major as `engines`; build stage `npm i -g pnpm@<packageManager version>`; runtime without pnpm/npm (existing AC).
- Docs (architect, same PR): `04-architecture.md` §7.1 Runtime row → `26.x ✓` (LTS until 2029-04, ADR 024), Package manager row → "pnpm (npm global, pin = `packageManager`, `pmOnFail: download`)"; CONTEXT §1 note, §6: replace the corepack-on-Windows line and the #145 line (Node 26, loop result), add "Node 25+ has no corepack"; ADR 024 → Accepted after AC 6; mvp-tasks M0-01 / M2-14 wording (Node 26, no corepack).
- README (lead-developer): Requirements "Node.js 26 LTS", "pnpm: `npm install -g pnpm` — the repo switches to the version in `packageManager`"; Getting started drops `corepack enable`.
- CLAUDE.md: no pnpm bootstrap line today → no change (verify `grep -n corepack CLAUDE.md` = empty).
