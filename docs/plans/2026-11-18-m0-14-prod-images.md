## Decisions
- **Runtime base = `gcr.io/distroless/nodejs26-debian13:nonroot@sha256:…`** (exists; amd64+arm64; uid 65532; ships no npm/corepack/shell by construction — 09 §14 holds without `rm -rf` hacks; libssl present for Prisma's schema engine). Build stages = `node:26-trixie-slim@sha256:…` (tag updated 2026-11-11, multi-arch). Fallback if distroless Node < 26.13.1 at implementation: `node:26-trixie-slim` + remove npm/npx/corepack + `USER node` (AC 1 test unchanged). Recorded as ADR 024 "Resolution (M0-14)" (ADR 024 deferred the choice to this task) — no new ADR.
- **No `pnpm deploy`:** pnpm 11 non-legacy deploy needs `injectWorkspacePackages` (breaks dev symlinks), `--legacy` is not frozen-lockfile-safe. Instead stage `prod-deps` (target platform): `pnpm fetch --prod` (lockfile only, layer cache) → `pnpm install --offline --frozen-lockfile --prod --filter @applyra/api...`; runtime copies `/app/node_modules`, `apps/api/{node_modules,dist,scripts/db-migrate.mjs,prisma,prisma.config.ts,package.json}`, `packages/contracts/{dist,package.json,node_modules}` (symlinks preserved). pnpm via `npm i -g pnpm@<packageManager without +hash>` read from `package.json` in the build stages only.
- **Stages:** `build` on `$BUILDPLATFORM` (full frozen install, `turbo build --filter=@applyra/api --filter=@applyra/web` incl. `db:generate`; JS output is arch-independent → no QEMU for tsc/vite) · `prod-deps` on `$TARGETPLATFORM` (only stage under QEMU: install + `prisma version` to bake the target's schema engine; `RUN test -n "$(ls node_modules/@prisma/engines/schema-engine-*)"`) · `api` · `web-build` (`ARG VITE_API_URL`, `VITE_AUTH_GOOGLE_ENABLED=false`) · `caddy`.
- **`prisma` moves to api `dependencies`** (same `~7.10.1`): the migrate entrypoint runs the CLI from the runtime image (12 §6 "same image as api"). Env in image: `CHECKPOINT_DISABLE=1`, `PRISMA_HIDE_UPDATE_MESSAGE=1`, `NODE_ENV=production`. `prisma.config.ts` is loaded by the CLI's own TS loader (verify in step 1; no `typescript` in runtime).
- **Entrypoints:** `ENTRYPOINT ["/nodejs/bin/node"]`, `WORKDIR /app/apps/api`, default `CMD ["dist/main.js"]`; compose `migrate` = `command: ["scripts/db-migrate.mjs"]`; worker = documented `command: ["dist/worker.js"]` from M3-01 (comment in compose + Dockerfile). Healthcheck (no shell): `node -e "fetch('http://127.0.0.1:3000/health/ready').then(r=>process.exit(r.ok?0:1),()=>process.exit(1))"`.
- **One Dockerfile `infra/docker/Dockerfile` + `infra/docker/docker-bake.hcl`** (targets `api`, `caddy`, group `default`, vars `PLATFORMS`, `VITE_API_URL`, `TAG`): one build graph, shared cache, same command locally and in CI; compose.prod uses `image: ${API_IMAGE:-applyra/api:local}` / `${CADDY_IMAGE:-applyra/caddy:local}` (deploy sets GHCR digests). Context = repo root; `.dockerignore`: everything except manifests/lockfile/workspace files, `apps/*/` sources, `packages/`, `infra/caddy/`; always `.env*` (no `!.env.example`, images need none), `node_modules`, `dist`, `.git`, `docs`, `e2e`, `**/test`.
- **Caddy:** `caddy:2.11.x-alpine@sha256` (2.11.9 released 2026-11-16 — take it once ≥ 3 days old, Renovate policy). Same Caddyfile local and prod: sites `{$APP_DOMAIN}` (file_server `/srv`, `/assets/*` without fallback → 404, else `try_files {path} /index.html`, `import spa_headers`, `encode zstd gzip`), `{$API_DOMAIN}` (`request_body max_size 8MB` = api drain cap, `reverse_proxy api:3000`, API headers stay helmet's), `{$ROOT_DOMAIN}` → redir app. `admin off`, `-Server`. `*.localhost` names get Caddy's internal CA automatically → no TLS branch in config. Non-root `USER 65532` + compose `sysctls: net.ipv4.ip_unprivileged_port_start: 80` (file caps don't survive `no-new-privileges`), `cap_drop: ALL`, `read_only`. Dockerfile deletes `/srv/_headers` (Pages-only file, not served).
- **Header single source:** `_headers` and the Caddy snippet use the same placeholder `{$API_ORIGIN}` (Caddy env syntax) in `connect-src`; `apps/web/scripts/headers.mjs` = `parseHeadersFile` / `renderHeaders(text, { API_ORIGIN })` (throws on any leftover `{$`), used by the test, smoke and deploy-prod. Rules: `/*` all §9.1 headers + `Cache-Control: no-cache`; `/assets/*` `! Cache-Control` then `public, max-age=31536000, immutable` (Pages joins duplicate headers with commas — detach is required).
- **CSP reporting deferred:** `Reporting-Endpoints` + `report-to csp-endpoint` need a Sentry CSP URL; Sentry web is R1 → omitted until then (an empty endpoint is an invalid header). Spec 09 §9.1 gets an "[R1, with Sentry web]" marker. Rest of the CSP verbatim.
- **Local hostnames `app.applyra.localhost` / `api.applyra.localhost` / `applyra.localhost`** instead of the AC's `https://localhost`: `app.localhost` vs `api.localhost` are different sites (eTLD+1 = `localhost` TLD rule) → Lax `__Host-` cookies would not flow; under `applyra.localhost` they are same-site exactly like prod `app.`/`api.`. Chrome/Firefox resolve `*.localhost` to loopback; curl gets `--resolve`.
- **compose.prod.yml** (overlay, `name: applyra-prod` → own volumes, never the dev DB): networks `edge` (caddy, api), `internal` (`internal: true`; api, migrate, postgres, redis), `outbound` (api); postgres/redis `ports: !reset []`, `networks: [internal]`; minio, minio-init, mailpit → `profiles: [dev-only]` (never started); `migrate` `profiles: [migrate]` (only via `run --rm`), `restart: "no"`. Every service: `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, logging `json-file max-size=10m max-file=5` (12 §9), `read_only` + `tmpfs /tmp` where the image allows (api, caddy, redis); postgres `user: postgres` (M0-08 CI pattern). Per-service `environment:` only — no shared `env_file` (api never sees the superuser/maintenance passwords; migrate sees only `MAINTENANCE_DATABASE_URL`). URLs composed in compose from hex passwords (URL-safe). api: `NODE_ENV=production`, `TRUST_PROXY_HOPS=1` (M0-10), `BETTER_AUTH_URL=https://${API_DOMAIN}`, `WEB_ORIGIN=https://${APP_DOMAIN}`, `DEMO_ENABLED=false`.
- **Valkey requires a password in prod** (`REDIS_PASSWORD`; defence in depth on `internal`): command writes `requirepass` into `/tmp/valkey.conf` (not argv), healthcheck via `REDISCLI_AUTH` env (verify valkey-cli honours it, else `VALKEYCLI_AUTH`). Local dev stays password-less.
- **Env generator** `infra/compose/gen-prod-env.mjs --out <file>` (random hex for every secret, domains default to `*.applyra.localhost`, refuses to overwrite, mode 0600); used by README, CI config check and smoke → no committed env with dummy secrets. `.env.prod.local` is git- and docker-ignored (`.env.*`).
- **Lint tools:** add **hadolint** (`hadolint/hadolint:v2.15.x@sha256`, `--failure-threshold warning`) in `deploy-ready`: Dockerfile best practice + shellcheck of `RUN`, which Semgrep's few Docker rules don't cover. Semgrep: add Dockerfile + docker-compose rulesets (verify slugs: `p/dockerfile`, `p/docker-compose`; CONTEXT says `p/docker` — use whichever resolves; semgrep fails on unknown) and `infra` to the scan scope.
- **CI `deploy-ready` job** (`if != schedule`, 30 min): checkout → setup-qemu + setup-buildx + bake-action (official docker actions, latest majors, full-SHA pinned) → hadolint → compose config checks (AC 4) → bake `linux/amd64` `--load` → AC 1 assertions → `smoke.sh` (AC 2, 3, 7) → bake both platforms `output=type=cacheonly`, `cache-to=type=gha,mode=max`. arm64 is built but not run (QEMU run = M0-14b smoke on a real ARM host if chosen). `permissions: contents: read` (no `packages: write` until M0-14b). The Stage 4 TODO comment is replaced.
- **deploy-prod.yml:** inputs `api_digest`, `caddy_digest`; guard step; Tailscale (OIDC) → render `/opt/applyra/.env` 0600 from Environment secrets over SSH → `compose pull` → backup marker (`pg_dump` as `backup`) → `compose run --rm migrate` → `compose up -d api caddy` → `pnpm build --filter @applyra/web` + `renderHeaders` on `dist/_headers` → `wrangler pages deploy` (pinned version via `pnpm dlx`) → curl `/health/ready` 200. Concurrency group `deploy-prod`, no cancel.

## Security notes
- No secret in images or build args (`VITE_*` are public; `.env*` docker-ignored; BuildKit cache contains only sources). Secrets reach containers as per-service env, never argv (Valkey conf file, `REDISCLI_AUTH`, compose interpolation).
- Non-root everywhere, `cap_drop: ALL`, `no-new-privileges`, read-only rootfs where possible; only Caddy publishes 80/443; Postgres/Redis unreachable from host and internet; `internal` network has no egress (proves migrate needs no downloads).
- `TRUST_PROXY_HOPS=1` relies on Caddy replacing a client-sent `X-Forwarded-For` (Caddy trusts no proxies by default — verify in Caddy docs during step 3); behind Cloudflare that hop is CF → `trusted_proxies` in M0-14b, otherwise all clients share CF's rate-limit buckets.
- `deploy-prod.yml`: Environment secrets only, `pull_request` never triggers it, guard step, SHA-pinned actions; `/srv/_headers` not served.
